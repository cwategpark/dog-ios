# Shopify 迁移架构评审草稿

状态：源码审计后的建议，业务选项尚待用户确认；不是上线完成声明。

来源：仓库 `cwategpark/dog`，基线提交 `b4cdc846756f6ed41db8c85aa67b6daca1933263`。本次只读仓库快照，没有访问原站运行接口、启动容器、读取仓库外凭据或调用付费模型。

## 已核实的迁移约束

- 站点是 WordPress / WooCommerce / Elementor 与自定义插件组合，不能把备份的 PHP 页面直接压成 Shopify ZIP。
- 首页、分类目录、全部商品、共享商品详情使用不同内容链；`daily-harness` 另有专属叙事模板。依据：`wordpress/docs/site-code-map/01-网站页面结构.md`、`06-项目依赖关系.md`。
- 当前列表查询强制 `_pawly_demo=yes`，并非全部已发布商品。依据：`wordpress/app/public/wp-content/plugins/pawly-platform/includes/data.php` 的 `pawly_products`。迁移时要明确取消旧演示标识门槛，才能符合“新上架商品自动展示”。
- 当前筛选有 pet / scene / kind 三轴，全部借用 WooCommerce 分类。Shopify 中需要明确可维护的数据模型与编辑入口，不能仅按商品标题猜类别。
- 选品问卷有确定规则、最多三件与本地回退，并有首单三件八折业务；后者涉及结算校验，不能只在主题里修改价格。依据：`pawly-pet-profile/includes/dify.php`、`suitability.php`、`bundle.php`。
- Dify 当前导出包含 23 个应用，混有未发布 Demo、历史客服和飞书/微信集成；不能把应用数量当成网站上线功能范围。依据：`workflows/README.md`、`workflows/dify/current/index.json`。
- 三视图是独立本机 Demo，README 明确未嵌入正式 WordPress 商品页。依据：`services/threeview/README.md`。
- 现有试穿与三视图依赖守护线程、进程内信号量与 job.json，不能保证进程重启后继续处理；现有代码可复用提示词与 provider adapter，任务调度应替换。依据：`services/adapter/workspace/image_service/tryon_service.py`、`services/threeview/service.py`。
- 首页 pet-experience 目录的快照资源总计约 117 MiB，不能整包随每个商品页首屏下载。该数值为本地文件总和，不是已测网络传输量。

## 建议的系统边界

建议先用一个代码仓库、一个模块化后端应用与独立 worker，不采用微服务或 Kubernetes。

```text
migration/
  theme/
    layout/theme.liquid
    templates/index.json
    templates/product.json
    templates/product.harness.json
    templates/collection.json
    templates/search.json
    templates/cart.json
    sections/
    snippets/
    assets/
    config/
    locales/
  backend/
    app/api/
    app/catalog/
    app/recommendations/
    app/pet_profiles/
    app/generation/
    app/fitting/
    app/providers/
    app/jobs/
    app/security/
    migrations/
    tests/
  deploy/
  tools/
  docs/
```

最终语言和部署栈待基础设施确认。现有生成与规则源码以 Python 为主，FastAPI + PostgreSQL、同镜像的 API/worker 两个进程是迁移成本较低的候选。初期可用 PostgreSQL 持久任务表和 `FOR UPDATE SKIP LOCKED` 领取任务，避免为了排队再维护一套 Redis；如果既有环境已有成熟队列，可直接接入。对象存储通过 S3 兼容接口；本地文件后端仅用于隔离开发。

Shopify 承担商品、变体、库存、价格、购物车、结账与订单的权威数据。独立后端保存问卷/宠物档案、规则版本、任务记录、生成输出及商品检索投影，不回写自己的价格库存。推荐结果只返回 Shopify 商品/变体标识，浏览器加购和结算由 Shopify 再校验可售状态。

## 主题模块与单点维护

- 默认 `product.json` 组合商品媒体、商品购买、商品说明、FAQ、推荐商品与试穿入口；新品没有指定特殊 suffix 时自动使用默认模板，无需为每个商品复制页面。
- `product.harness.json` 仅组合不同顺序/配置或专属 section，继续复用商品价格、变体与购买 snippet。商品描述和库存不能在模板中硬编码。
- 首页按 3D 开场、场景商品带、生活方式叙事、品牌/资质说明、全球愿景等独立 section；分类页按品牌入口、筛选、商品网格、试穿专题拆分。
- 全站导航、页脚、商品卡片、价格、图标、购买表单、节日层各有共享入口，不复制到每个模板。
- 节日功能由一个共享 `seasonal-effects` 入口和一个全局主题设置控制；默认商品模板和商品专属模板都经过该入口。新增圣诞视觉只改这个模块及其配置即可，不在每个商品添加代码。
- 节日展示范围应由设置选择：全部商品/指定系列/标签；是否按商品分类自动切换节日视觉仍需确认。关闭时不下载动画脚本。减少动态效果模式显示静态装饰。
- Theme Editor 为运营修改内容、模块顺序、商品系列与节日开关的入口；商品特殊属性使用统一命名空间的数据定义，文档给出含义、类型、默认值与约束。

注意：主题不能自由重写 Shopify 托管结账与新版客户账户，不能承诺它们与 WooCommerce 页面逐像素相同。优惠逻辑必须落到 Shopify 支持的折扣机制；能否完整复刻需核对店铺计划、应用安装方式和可用功能后决定。

## 商品同步与默认模板

商品上架后，主题直接读 Shopify Liquid product/collection 对象，因此展示无需等待后台“每日同步”；后台同步只服务推荐/适用条件检索。

后台首次全量同步后，用平台商品变更/删除及相关库存事件驱动增量投影，并定期对账。回调入口校验原始请求体签名，先持久接收再尽快响应。以店铺、事件标识建唯一约束；乱序事件通过更新时间/重读当前数据处理。投影记录 Shopify GID、状态、发布渠道、变体、适用规则、更新时间，不依赖 WordPress 数字 ID。

“有 ACTIVE 状态”与“已发布到 Online Store”应区分。自动展示规则还需确认库存为零商品是否显示，以及首页是否只显示运营选定的精选系列。普通新品自动使用默认模板，不需产品 webhook 逐件强行改 `templateSuffix`；已有明确指定其他模板的商品是否重置必须另行确认。

## 工作流改为确定业务模块

- 目录规范化与选品：迁出纯函数并保留规则边界测试；相同输入与目录快照应得到可解释结果。AI 排序只能作为已通过适用性过滤的候选列表上的可选增强，不得发明商品或越过安全/适用规则。
- 宠物照片试穿：表单验证、同意记录、受控上传、读取 Shopify 商品素材、提交异步任务、查询状态、受权下载。前台只提交产品/变体标识和受控上传标识，不可提交任意远程商品 URL 让服务器拉取。
- 卡通与 3D：从已经成功且属于该用户/会话的试穿结果创建派生任务。provider adapter 与业务任务分开，允许更换模型而不改主题。
- 默认猫咪 3D 贴合：确定的商品资产与校准 manifest 可以直接返回版本化配置；只有需要识别新商品佩戴位置时才调用 AI。手动校准应保留审计与版本、模型指纹不一致则失效。
- 邮件/飞书/采集：先确认是否属于此次网站服务范围，不能把所有归档自动开启；也不要在本地验收时运行真实发信/外部写入。

## 异步任务可靠性

采用持久状态机：`queued → running → succeeded / failed / cancelled / needs_review`。保留阶段进度、尝试次数、租约、心跳、输入摘要、业务/模型/提示词版本、输出元数据及脱敏错误码。

提交端提供 Idempotency-Key，按店铺+主体+操作建立唯一约束，并保存规范化输入摘要；同 key 不同请求体返回冲突。任务与待执行事件在同一数据库事务中落盘；worker 以带期限租约领取，避免 API 崩溃漏排。

外部生成请求存在“已收费但响应丢失”的不确定状态，不能宣称 exactly-once。供应商支持幂等键时传递同一键；可查任务状态时先查后续跑；两者都不支持时进入 needs_review，不能无限自动重试。网络读请求和安全操作才按上限指数退避。每阶段成功输出持久化，恢复时不重新生成已完成阶段；三视图侧/背依赖正面图，不能无条件并行三次调用。

按店铺/用户/provider 配置并发、提交频率和费用配额；队列满时给出明确状态。用户取消只能保证未执行阶段停止，已发给供应商的生成需按其取消能力处理。输入图片与输出保留期限作为待确认策略，后台清理任务需删除对象及关联下载权限。

## 认证与数据保护

- 主题到业务后端建议走店铺应用代理，核对签名、店铺、时间与重放窗口；代理签名仅证明请求经过 Shopify，不能取代每项任务的主体/所有权校验。
- 访客是否允许生成待确认。若允许，后端签发受限会话或任务能力 token，数据库绑定 owner；不可把猜不到的 job_id 当全部授权。登录客户由验证后的 Shopify 主体建立映射，不接受浏览器自报 customer_id。
- 上传设置格式、大小和像素限制，解码重写去元数据；采用受控上传/存储标识，拒绝任意 URL 与私网地址。商品图只读自店铺已知 CDN 素材；避免 SSRF。
- 原始照片与生成结果为私有对象，以短期签名 URL 或鉴权下载提供，不能公开列举目录。密钥仅存运行环境/secret manager，不进入 Liquid、JS、仓库与日志。
- 宠物档案收集最少信息；同意版本、时间、用途和撤回/删除均有记录。AI 只接收完成任务所需图像和匿名宠物属性，不默认发送姓名/邮箱。
- 后台管理员身份与顾客分开；修改校准与运行配置使用 Shopify 后台已验证会话、最小权限与审计日志。

## 性能方案与验收目标

- 商品/系列/搜索首屏由 Liquid 服务端输出，购买和基本浏览不依赖 AI 后端或 3D 模型成功。
- 以常用移动网络下 LCP ≤2.5 s、INP ≤200 ms、CLS ≤0.1 作为目标，目标需用真实 Shopify 预览环境和规定设备/网络测量；当前尚无该实测结果。
- 首图使用 Shopify 图片转换与响应式尺寸并保留宽高；仅首屏关键图优先，其他图片 lazy。视频默认海报，按可见性加载，移动端限制自动播放成本。
- CSS 按基础/页面/组件组织；3D、试穿、节日脚本按对应 section 和用户交互或接近视口再 import。无 3D 商品不加载 Three.js/模型查看器。不能把全部首页资源复制到所有商品页。
- 3D 资产评估几何压缩、纹理压缩/尺寸、材质数量和移动端降级；需要可重建源码、依赖锁与资产许可清单。动画离屏/后台暂停，支持减少动态效果和 WebGL 失败时的静态替代。
- API 不阻塞 storefront 渲染；推荐有快速确定规则回退；生成使用退避轮询并在页面隐藏时暂停。错误和加载状态预留空间，避免布局跳动。
- 建议发布前明确每路由关键 CSS/JS 和首屏图/视频/模型的预算，检测打包体积回归；不能用尚未测量的性能数字宣称优化完成。

## 数据迁移、上线与回滚

1. 保持原站和运行容器原样，在新目录与新数据库开发；不要原地恢复备份 SQL 或沿用原容器名称/端口/挂载卷。
2. 先导出只含计划迁移的公开商品/媒体/扩展字段，生成 dry-run 清单与 WordPress ID → Shopify GID 映射。Shopify 已有商品时以 SKU 等稳定标识核对冲突，不覆盖现有数据。
3. 客户、订单、宠物档案和原始照片不自动迁移；单独确认范围和合法保留/删除策略后再执行。仓库脱敏快照不能作为真实客户数据来源。
4. 在开发店铺或未发布主题验收页面与交易路径，外部模型采用 fake provider 测试正常/超时/重复/重启，再做经授权的小规模真实模型验证。
5. 上线顺序：后端与数据库迁移、应用配置/权限/回调、目录同步、未发布主题安装、联调与验收、最后发布主题。全程保留前版本主题与后端镜像；数据库采用向后兼容迁移，生成资产不随回滚删除。
6. 验证失败可切回旧主题/后端版本，停止新任务接收但保留状态；不能把“删除全部新数据库”作为回滚方案。

## 应先确认的业务问题

| 问题 | 建议默认方案 | 影响 |
| --- | --- | --- |
| 交付范围是本地包、上传未发布主题还是最终上线；是否已有店铺 | 先本地+未发布预览验收 | 连接/权限/真实验证条件 |
| 忠实保留哪些页面和重型 3D/视频交互；是否接入未发布 Demo | 保留现站已使用功能，Demo 单列 | 页面复刻与性能预算 |
| 新品进入哪些位置，是否保留手工指定商品模板 | 默认详情自动，目录随发布自动，首页精选由系列配置 | 避免首页无序与误覆盖 |
| 首单三件八折、问卷自动弹出、AI 排序是否保留 | 保留确定推荐；优惠和主动弹窗需确认 | Shopify 折扣、客户识别、营销体验 |
| 访客是否允许生成；每人额度与费用承担 | 待用户确认 | 防滥用、登录流程、成本 |
| 原图/结果保留多久；客户历史和订单是否迁移 | 不默认迁客户/订单，期限需明确 | 隐私、存储费用、删除任务 |
| 后端部署环境、地区、模型提供商与已有账号 | 延用已验证 adapter、通过环境配置接入 | 可用性/速度/运维成本 |
| 店铺语言/币种与售卖地区 | 从现站多语言范围逐项确认 | Shopify Markets/翻译与税运费配置 |

以上问题不能由归档的 Demo 名称推断为已确认需求。无需等待答案的工作包括源码审计、映射设计、隔离目录、规则抽取与假 provider 的可靠性验证；依赖业务选择的实现和真实外部写入应在答案明确后进行。
