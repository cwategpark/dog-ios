# 加载速度方案与验收

原快照 `pet-experience` 资源目录约 117 MiB，其中单个宠物模型约 44 MiB；这是文件总量，不是本次实测网络传输。本次遵循用户确认，保留核心品牌与媒体，简化地球/物理模拟，不把原 WordPress iframe 和全部模型复制进首屏。

## 加载策略

- 商品、集合、搜索、价格和购买表单由 Liquid 输出。AI、GPU、3D 或后端失效不能阻塞基本浏览和购买。
- 基础 CSS/交互轻量加载，商品、问卷和校准查看器按相关页面/操作加载；原生商品模型位于 template 中，点击 3D 后才实例化。小猫服装约 2.8 MiB 以及 Three 依赖只在明确请求结果后加载。
- 商品图片使用 Shopify `image_url/image_tag` 响应式转换。首屏主图 eager/high，其余 lazy、固定宽高，避免布局跳动；首图不通过动画延后可见。
- 图片海报先显示，模型/WebGL失败回到图片；无模型商品不会自动下载查看器。没有商品数据时显示空状态，不用假商品填充线上主题。
- 离屏/后台暂停 3D；减少动态效果设置下取消持续动效。节日效果共享一处设置，默认关闭，不阻塞购买。
- 后端只返回异步任务，前端退避轮询、隐藏页暂停；收费请求结果不明时进入待核查，不反复重发。

## 验收目标与证据边界

目标店移动端以 LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1 为目标，在固定设备、CPU/网络节流、相同数据/应用条件下测量；当前没有把本地开发机结果说成真实 Shopify 达标。

本地验证覆盖 1440/390/320px 的首页、集合、商品、搜索、购物袋、404；检查横向溢出、脚本异常、规格切换、缺货禁购、图片回退与访客问卷。真实 Edge WebGL 另外验证了两模型合成、手机取景、键盘操作和无 WebGL 回退。

运行 `pnpm check` 记录总资源和大文件；主题 ZIP 体积不能当首屏下载量。正式验收还要记录真实 Shopify 未发布主题每路由 HAR、Lighthouse 中位数、关键首屏字节、脚本长任务与可交互时间。新增业务脚本、模型或营销应用必须做同条件前后对比。

参考：[Shopify theme performance](https://shopify.dev/docs/storefronts/themes/best-practices/performance)。
